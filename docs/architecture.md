# PhantomCurl Architecture

PhantomCurl combines a network client with a lightweight JavaScript and DOM sandbox. It is deliberately smaller than a real browser: it can make TLS-impersonated HTTP requests, parse HTML, execute supported classic scripts and a limited static ES-module subset, and expose the resulting DOM to Python.

## Network Layer
Instead of standard `httpx`, the project uses `curl_cffi`. It allows specifying `impersonate="chrome"`, making the request use a supported browser-like TLS profile. One `NetworkSession` is shared by a `PhantomClient` and every page it creates, so cookies persist across requests.

`RetryConfig` belongs to this layer. It controls retryable status codes, allowed methods, and exponential backoff. Its default is one attempt, so enabling retries is an explicit client decision. A request-level `retry_config` replaces the client's policy for that request, while `max_attempts` changes only the attempt limit and preserves every other field of the selected policy. Neither form mutates the client's configuration.

`StorageState` is a JSON-serializable snapshot of the cookie jar and origin-scoped local-storage data. `NetworkSession` owns this durable state: every new page gets a fresh JavaScript context, but receives the cookies and local-storage entries that belong to its origin.

## Environment Layer
The environment has two parts:

1. **QuickJS** compiles and executes JavaScript in memory. Every page navigation starts a fresh context with time and memory limits, preventing page-local JavaScript and DOM state from leaking between navigations. Promise jobs are drained by `Page`; zero-delay timers run automatically, while delayed timers require `Page.run_event_loop()`.
2. **Linkedom** provides the virtual `window` and `document` objects. The network response HTML is parsed into this DOM, which can then be queried and manipulated through `Page` and `Element`.

## Page lifecycle

`Page.goto(url)` fetches the document through the shared network session, uses the final response URL as the base URL, parses the HTML, and runs supported inline, external, and module scripts in document order. Relative external scripts and static module dependencies are fetched through the same session and receive a `Referer` header. `location`, `document.referrer`, `navigator.languages`, `document.cookie`, `console`, screen metrics, timers, page-local `fetch()`, `localStorage`, `sessionStorage`, `URL`, `URLSearchParams`, `Image`, and the baseline `performance` clock are installed before page scripts run.

During script execution, `document.readyState` is `loading`. After the supported initial scripts finish, `Page` changes it to `interactive` and dispatches `DOMContentLoaded` on `document`; it drains supported work and newly inserted scripts before changing the state to `complete` and dispatching `load` on `window`. This is a deliberate lifecycle approximation: PhantomCurl does not model the browser parser's blocking/defer/async phases or wait for image and stylesheet resources before `load`.

Assigning `location.href` or calling `location.assign()`/`location.replace()` from JavaScript does not replace the Python page in the middle of a JS evaluation. Instead, it appends the requested address to a JS-side queue. After `Page.goto()` finishes its lifecycle, `Page.evaluate()` finishes its immediate work, or `Page.run_event_loop()` becomes idle, `Page` reads the queue, resolves the last address against the current page URL, allows only HTTP(S), and follows it with `Page.goto()`. A safety limit stops a chain after ten automatic navigations. Delayed timers still need `Page.run_event_loop(timeout)` to become due; once a due timer queues a navigation, that navigation is followed automatically. Full browser session history is not modeled across documents, so `replace()` currently has the same document-level result as `assign()`.

The lightweight `history` facade supports SPA routing within the current document. `pushState()` adds an entry, `replaceState()` changes the active entry, and `back()`, `forward()`, and `go()` move through those entries while synchronously dispatching `popstate`. Each stored state is JSON-cloned and each supplied route must resolve to the current origin. These operations update the JavaScript `location` fields only: they do not fetch HTML, replace the DOM, or modify Python's `Page.url`. The history starts fresh after each full page navigation; browser session history across documents, `go(0)` reloads, scroll restoration, hash-change events, and full Structured Clone semantics are intentionally absent.

`document.cookie` writes and `localStorage` mutations are first queued by JavaScript, then persisted to the shared `NetworkSession` while `Page` drains the runtime. The local-storage facade supports `getItem()`, `setItem()`, `removeItem()`, `clear()`, `key()`, and `length`. It is deliberately smaller than the browser API: named-property access, `StorageEvent`, and live synchronization to already-created pages are unavailable.

`sessionStorage` supports the same methods but is owned by one `Page`, not by `NetworkSession`. The `Page` keeps origin-scoped session-storage dictionaries outside the JavaScript context so they survive `Page.goto()` but are invisible to another `Page` and omitted from `StorageState`.

`Element.click()`, `Element.type()`, and `Element.dispatch_event()` execute registered DOM event listeners synchronously. Their handlers can mutate the DOM immediately and can queue `fetch()` calls, Promise jobs, or timers. Each Python interaction automatically drains fetches, Promise jobs, and zero-delay timers before returning; it then discovers and executes newly inserted supported script elements. Timers scheduled for the future still require `Page.run_event_loop(timeout)`. `Element.click()` additionally implements the normal default action for an `<a href>` in the same browsing context: after event dispatch it queues navigation unless the handler called `preventDefault()`. It initializes checked checkbox/radio controls from parsed HTML and handles their click-time toggle/group behavior with `input` and `change` events. A click on a submit button can also submit a GET form after a cancellable `submit` event: the current subset serializes textual controls and checked checkbox/radio controls to the action URL. POST requests, files, validation, multiple-select controls, programmatic `form.submit()`, links with `download` or a target other than `_self` remain outside the current scope.

The lightweight `URL` and `URLSearchParams` polyfills support normal HTTP(S) URL construction, resolving a relative reference against a base URL, inspecting or changing common URL components, and reading or mutating query-string pairs. `new Image()` creates a detached DOM `<img>` that scripts can configure and insert, but PhantomCurl does not fetch or decode its resource and does not emit its loading events. `performance.timeOrigin` and `performance.now()` provide a basic elapsed-time clock; Performance Timeline APIs are outside the current scope. The URL polyfills are intentionally not a complete WHATWG URL implementation: object-URL helpers, internationalized domain-name processing, and malformed percent-escape recovery are outside the current scope.

`fetch()` is Promise-based and same-origin by default. `OriginPolicy` can allow an explicit target-origin allowlist or all HTTP(S) origins. It is an application-controlled access rule, not CORS: it sends no preflight and does not read `Access-Control-Allow-*` headers. Cross-origin requests retain the shared session's ordinary domain-based cookie behavior because browser `credentials` modes are not implemented. Fetch supports `GET`, `HEAD`, `OPTIONS`, `POST`, `PUT`, `PATCH`, and `DELETE`, string request bodies, `text()`/`json()` response methods, and plain-object headers or the implemented `Headers` subset. The page-side `Headers` class normalizes field names, supports common mutation and iteration methods, and is serialized into the Python request bridge. The page-side `FormData` subset stores string fields, preserves duplicate names, and is serialized as a `multipart/form-data` body with an automatically generated boundary. `Blob`, `File`, and `new FormData(htmlFormElement)` remain unsupported. Responses expose a mutable `Headers` snapshot; `Set-Cookie` is deliberately hidden from page JavaScript. `AbortController` and `AbortSignal` can reject a queued fetch and remove it before Python starts the blocking HTTP call; they cannot interrupt a request already being executed by `NetworkSession`.

`XMLHttpRequest` uses the same queue and `FetchInterceptor` as `fetch()`, so it shares session cookies, the `Referer` header, supported HTTP methods, and `OriginPolicy`. Its page-side facade supports asynchronous `open()`, `setRequestHeader()`, textual `send()`, `abort()`, `getResponseHeader()`, `getAllResponseHeaders()`, numeric ready states, and the `onreadystatechange`, `onload`, `onerror`, and `onabort` callbacks. A text body receives `Content-Type: text/plain;charset=UTF-8` unless the script set its own value. It intentionally excludes synchronous mode, event listeners via `addEventListener()`, upload/progress events, binary or document response types, timeout handling, credentials modes, and cancellation of an HTTP request already executing in Python. Draining continues while a completed `fetch()` or XHR handler queues another supported request, allowing ordinary chains between the two APIs to finish in one page operation.

The static ES-module loader applies the same `OriginPolicy` to its entry modules and static dependencies. It supports named, default, namespace, and side-effect imports; common default exports; named/star/namespace re-exports; executes direct static dependencies before a module body; and exposes live-like bindings for this supported static subset. It still lacks dynamic imports, `import.meta`, top-level `await`, and full ESM instantiation/evaluation semantics, so complex circular module graphs are not browser-equivalent. CORS, module redirects, streams, and `Request` are unsupported. The detailed design and current syntax boundary live in [the ModuleLoader walkthrough](module-loader-walkthrough.md).
